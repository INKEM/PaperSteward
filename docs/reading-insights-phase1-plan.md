# 阅读回顾第一阶段：分批实施计划

> 日期：2026-10-25。状态：R1-01 至 R1-06 已实施（2026-10-26）；独立复核发现 6 组返工项，尚未完整验收通过。原发布记录见第 12 节，最新结论见第 13 节。
> 对应范围：[功能设计草案第 13 节第一阶段](reading-insights-design.md#第一阶段可靠回顾与手工积累)。
> 目标：先交付可靠的全历史事实视图、周／月回顾及手工资产积累，建立后续知识提炼可依赖的数据基础。

## 1. 第一阶段交付边界

完成后，用户能够从“归档 → 阅读回顾”进入以下流程：

1. 查看本周、本月或全部历史的阅读事实，分清新读、历史补录、反馈修订和缺失数据。
2. 在导入或归档详情中选填／修正实际阅读日期，允许只记得月份或日期未知。
3. 手动生成并保存事实版周报、月报，查看历史版本，导出 Markdown／JSON。
4. 为已读论文手工记录一条收获或问题，关联一篇或多篇来源，后续修订或标记问题已解决。
5. 找回这些资产，在回顾中看到本期整理活动；全部历史页同时提供资产入口。

首期不包含模型归纳、自动画像、跨文献推断、方法／证据自动抽取、重读次数记录、跨工作区汇总或新增 CLI。不会调整现有偏好分、标签补给、检索规划、评分权重或研究档案。所有分析均在本机完成，不新增授权开关、定时任务或网络调用。

“终身画像”的首期交付名称为“全部历史”：显示事实和手工资产，不生成关于用户能力或稳定偏好的判断。

## 2. 代码现状与实施影响

本计划依据当前代码，实施前应再次核对主线变化。

| 现有位置 | 已有能力／需要注意的事实 | 实施选择 |
|---|---|---|
| `reading/archive.py::read_archive` | 校验归档哈希，叠加最新反馈，返回全部反馈修订 | 保留现有接口语义；新增按截止时间读取的分析投影 |
| `reading/archive.py::list_archives` | 页面分页上限 200，但内部遍历归档并逐篇读取 | 不以分页页面接口循环汇总全库；新增批量读取路径 |
| `reading/archive.py::archive_imported` | 标记 `origin=import`，同时补发 `paper.done` 供补给使用 | 回顾按归档来源分流；不改完成事件及补给语义 |
| `reading/actions.py::apply_action` | 完成冻结快照；修订追加 `Rating`；支持请求幂等 | 复用原始反馈；阅读日期和手工资产用独立服务，不扩展阅读状态机 |
| `delivery/contracts.py` | 归档、动作、导入请求契约集中于此 | 新分析契约放在独立模块；仅为导入新增可选日期输入 |
| `storage/models.py` | `RatingRow` 以论文 ID＋创建时间标识一个反馈版本 | 来源可引用具体反馈版本，不能只引用“最新反馈” |
| `api/deps.py`、`api/workspace_runtime.py` | 按 cookie 解析独立工作区、会话工厂和任务管理器 | 新接口全部使用当前工作区依赖，不使用全局缓存或全局数据库 |
| `jobs/ui_flow.py::UIFlowManager` | 工作区内任务互斥，已有提交、取消、重试和进度；恢复类型列表写死 | 保存报告复用任务编排，但需补齐回顾类型、恢复和完成跳转 |
| `api/form_utils.py`、`api/html.py` | 表单来源检查、输入读取、转义、页面与导航组件 | 新页面沿用现有表单及错误反馈规范 |
| `storage/workspace.py` | 按 metadata 反向拓扑顺序清空全部业务表，先备份数据库 | 新表自然进入清空范围；仍须补重置预览及备份内容回归 |
| `migrations/versions/0020_import_archive.py` | 实施起点为 `0020`；现 head 为 `0023` | 计划分三次追加迁移；执行时取下一个可用编号，不改旧迁移 |

特别注意两个不能直接复用的入口：

- 最新归档展示不能用于历史统计，否则今天修订的 5 分会出现在上个月的原始报告中。
- `paper.done` 事件不能直接等同真实阅读，因为导入旧论文也会生成该事件。

## 3. 先冻结的时间与统计契约

### 3.1 阅读时间独立于冻结归档

新增旁路的“阅读时间修订记录”，不修改 `archive_snapshot.content_json` 及其哈希。历史查询按记录时间选择当时有效版本。

| 情况 | 首期默认解释 | 用户更正 |
|---|---|---|
| 系统内完成，快照含 `reading.completed_at` | 以标记完成时间作为阅读记录，注明是系统记录时间 | 可另行声明实际日期、月份或未知，追加修订 |
| 已有导入归档 | 阅读时间未知，导入时间已知 | 可在详情页补记日期或月份 |
| 新导入归档 | 默认未知；可在原确认表单选填 | 输入与导入在同一事务内保存 |
| 旧快照内容缺失 | 仅使用可核查的既有时间／来源证据；不能可靠还原则未知 | 允许补记，不从当前论文元数据猜测历史 |

日期精度为“日／月／未知”。月精度不伪造具体日期：进入对应月份统计，周报中只显示“阅读日不详的相关记录”，不计入确定的周阅读量。自选周期若只覆盖部分月份，也单列月精度记录，不自动纳入精确计数。

系统完成时间保留 UTC 时刻，查询时按报告时区归日；用户声明的日期／月份为自然日历值，切换时区不移动它们。来源性质为系统完成、外部导入或来源未明，与时间精度分开记录。

日期不能晚于填写时工作区的当前日期／月份；未知允许明确清除。修改日期不会重发完成事件、改变归档时间或触发偏好重算；它只影响新回顾中的阅读时间解释。

### 3.2 两条时间轴和两种回顾模式

- **活动时间**：论文实际阅读发生在哪天／哪月，用于阅读分布。
- **记录时间**：系统何时知道这篇归档、日期声明、反馈修订及资产版本，用于判断当时可见内容。

周期统一表示为本地 `[开始日, 结束日次日)`，转换为 UTC 查询边界；历史截止时刻为周期结束，本期截止时刻为开始采集快照的时刻，均使用排他上界。报告保存工作区时区，不从服务器本地时区推导。

首期提供两种明确的模式：

| 模式 | 知识截止 | 使用场景 |
|---|---|---|
| 当时记录 | 历史周期结束；未结束周期则截止采集时刻 | 还原当时已知的阅读和反馈，默认模式 |
| 现在重新回顾 | 本次采集时刻，活动周期仍是选定历史周期 | 纳入后来补录或更正；标明后补记录数，不冒充原始报告 |

不能仅按阅读日期过滤：一篇后来补录的旧论文，即使阅读日期属于过去，也不得进入“当时记录”。所有源记录先受知识截止限制，再按活动日期归属。

### 3.3 指标定义

| 指标 | 口径与分母 |
|---|---|
| 本期阅读独立文献数 | 阅读日期／月份明确属于本期且在知识截止前已记录的不同论文数；系统内与外部来源可分组 |
| 本期系统内完成数 | 本期发生的系统完成记录，作为阅读时间更正后的辅助对照，不能与阅读独立文献数相加 |
| 本期补录数 | 本期进入归档的外部已读论文数；即使声明本周读完，仍保留外部来源，阅读量与补录量可能重叠 |
| 阅读时间未知数 | 当前分析范围中不能归属活动周期的归档数量；周期页显示为“截至截止时刻的未定日期库存” |
| 已评分／有备注覆盖率 | 本期阅读集合中，截止前最后有效反馈的有效篇数／本期阅读篇数；补录集合可单独展示 |
| 评分分布 | 1–5 分及未评分各档篇数；空集合覆盖率为“暂无”，不显示虚假的 0% |
| 反馈变化 | 本期发生的非初始反馈修订记录；分别显示评分／备注实际变化事件数和涉及论文数，初始归档不算修订 |
| 阅读方式分布 | 本期阅读集合中的原始实际阅读方式；无数据单列未知 |
| 主题分布 | 使用归档时分类版本及主标签；缺标签单列，跨版本同名不直接合并 |
| 发表年代分布 | 使用冻结的发表时间；没有则未知，不用当前论文信息回填 |
| 资产整理活动 | 本期创建、修订、关闭问题等操作数及不同资产数；不会增加已读篇数 |
| 全部历史文献数 | 截止前所有独立归档；包含未定阅读日期的论文，独立列出数据完整性 |

主标签分布互斥；副标签如展示须另标“可重叠覆盖”。首期不计算平均分趋势、增长排名、阅读时长、领域掌握程度或推荐准确率。

反馈实际变化从相邻反馈版本比较得到：备注变更只算备注，评分变更只算评分；“清除为 null”也是有效变化，不能退回初始值。记录重复写入但值未变，不制造一次认知变化。

## 4. 分层与新增模块

建议新增 `reading/insights/`，将事实回顾与现有评分及遗留日报分开：

| 层次／模块（拟） | 职责 | 依赖边界 |
|---|---|---|
| `contracts.py`、`periods.py` | 严格输入／输出模型、日期精度、周期及截止语义 | 不依赖 ORM、路由或模型服务 |
| `projection.py` | 批量读取归档及截止前的反馈、日期、资产版本，输出纯数据 | 只读存储；不调用 `read_archive` 逐篇取最新值 |
| `aggregate.py` | 去重、分组、覆盖率和变化清单 | 纯计算，可用小型固定数据做单元测试 |
| `timeline.py` | 阅读日期修订、并发校验、导入时初始化 | 不修改论文状态、归档或评分通道 |
| `reports.py`、`export.py` | 事实报告编制、保存、读取、版本与导出 | 不依赖 `Digest`、投递或 `refresh_queue` |
| `assets.py` | 手工收获／问题、来源、修订及问题状态 | 只引用已读归档；不调用 LLM 或修改 `Rating` |
| `storage/insights.py` | 日期、报告、资产的仓储与批量查询 | 事务由服务／调用方明确管理 |
| `api/insights.py`、`api/insights_pages.py` | JSON 路由及页面表单、错误反馈 | 调用服务，不在路由重复计算统计 |
| `jobs/ui_flow.py` 的回顾分支 | 调度报告生成、取消、恢复和结果引用 | 使用当前工作区运行时；统计逻辑留在服务层 |

新 Pydantic 契约统一 `extra="forbid"`。回顾是应用数据，不必注册为 LLM JSON schema；首期不新增 prompt，也不扩展 `SCHEMA_MODELS`。若实施时改变这一决策，须同步冻结测试。

页面复用 `api/html.py` 的外壳、分页与输入组件，从现有归档页和归档详情增加入口。只在必要位置修改较大的 `api/pages.py`，新增功能不继续堆入该文件。

## 5. 存储与迁移拆分

以下名称和字段用于说明约束，最终以每批迁移和契约为准，不提前创建后续阶段的占位表。

### 5.1 阅读日期修订：第一笔迁移（预计 `0021`）

新增 `reading_time_revision`：论文 ID、递增版本、记录时间、日期精度、声明日／月份及来源依据。论文 ID 指向归档；`(paper_id, revision)` 唯一。

- 日、月、未知三种取值在应用与数据库均校验互斥；月可以保存年月或规范化月份，但不能对外伪装成精确日。
- 写入先校验 `expected_revision`，防止两个详情页相互覆盖；数据库唯一约束兜底。
- 既有归档按原始快照进行只读兼容投影，不批量补写看似用户确认的记录。新日期记录由显式更正或带日期的导入产生。
- 不新增／改写 `rating`、`event`、`archive_snapshot` 的既有内容，也不复用 `ConfigRow` 保存个人时间数据。

### 5.2 报告快照：第二笔迁移（预计 `0022`）

新增 `reading_report`：ID、报告类型、周期、时区、回顾模式、采集截止、生成时间、契约／算法版本、输入指纹、冻结正文及校验哈希、生成运行 ID。相同报告系列按生成顺序展示版本。

- 运行 ID 唯一，重试不重复创建报告；可再用规范化请求和输入内容指纹去重相同结果。
- 指纹覆盖实际参与的归档 ID／哈希、反馈版本、日期版本、资产版本、时间语义和算法版本；不以 `MAX(created_at)` 或总篇数代替数据指纹。
- 仅生成时间不同且实质输入未变时，返回已有快照并保留其原截止时间；周期从“未结束”变为“已结束”属于语义变化，应生成新快照。
- JSON 正文为读取时的唯一内容来源。打开旧报告不能再次拼接最新评分、日期或资产正文。
- 不复用以日期为主键的 `digest` 表，不产生 `delivery`，也不把完整私人正文放入运行进度。

### 5.3 手工资产：第三笔迁移（预计 `0023`）

新增 `reading_asset`、`reading_asset_revision`、`reading_asset_source`：

- 资产身份稳定；正文及状态追加版本，用版本号做乐观并发校验，避免静默覆盖。
- 首期仅两类：收获、问题。收获为有效／归档；问题为待解决／已解决／归档，不引入重型任务管理。
- 每个版本保存标题、用户正文、适用说明和来源集合；来源指向归档哈希，可选引用具体反馈版本。
- 每个资产至少关联一篇已读文献，允许多篇；来源只引用当前工作区中实际存在的归档，不能相信客户端传来的来源内容或确认状态。
- 来源归属于资产版本，而非随时变动的全局列表；修改关联来源也创建新版本。
- 不建立资产到“当前版本”的循环外键，可按最大版本读取当前状态，方便现有拓扑清空逻辑。

三笔迁移均须与 `Base.metadata.create_all` 一致。迁移 head 编号在落地时重新分配；不得为遵守本文编号覆盖其他工作新增的迁移。

## 6. 六批落实顺序

依赖关系：`R1-01 → R1-02 → R1-03 → R1-04 → R1-05 → R1-06`。每批以独立变更或检查点收敛，不将日期、报告和资产三个存储变更混在一笔不可审阅的大改中。

### R1-01：时间契约与历史分析投影（已完成）

**交付**：一个有固定样例验证的只读分析底座，不增加数据库表或浏览器入口。

工作项：

- 建立周期、知识截止、来源、阅读时间精度、反馈版本的严格契约。
- 读取源以归档为准，批量取得截止前反馈；导入来源先读冻结标记，有可靠既有来源证据才补充判断，否则为来源未明。
- 从原始归档提取阅读方式、标签版本与可用元数据；缺失时不借当前论文或当前分类法填充历史。
- 拆开初始反馈和真实修订，确保 null 清除、未来反馈排除、同篇多次修订不重复计数。
- 抽出归档内容哈希验证的公共只读辅助函数，供旧接口与投影复用，避免改变 `ArchiveRecord` 契约。
- 查询随数据批次增长，禁止每篇多次查库；统计不受页面 `limit=200` 限制。

验收与测试：纯逻辑的时区／周月边界；真实 SQLite 的历史反馈选择、缺内容快照、导入完成事件分流及超 200 篇全量覆盖。加入有针对性的批量查询数检查，避免只验证统计值却留下逐篇查询。

完成条件：给定同一源快照、周期与截止，得到稳定投影；既有归档读取和导出回归不变。此批只建立开发可验收能力，不对用户宣布已提供回顾。

### R1-02：阅读日期补记与导入分流（已完成）

**交付**：用户可以为导入论文及现有归档补记日／月／未知，且历史记录可追溯。

工作项：

- 落实第一笔迁移及日期仓储、服务；原归档作为兼容默认，新声明追加记录。
- 为 `ImportReadPaperInput` 增加向后兼容的可选阅读时间输入，贯通导入确认表单、领域调用及原子事务。
- 归档详情显示“归档于”和“阅读时间”两个值，保留原反馈修订入口；增加独立的补记表单。
- 将旧导入的“完成于导入日”文案改为真实的导入／归档说明，不再把录入日期当成阅读日期。
- 新写接口验证归档存在、日期范围和预期版本；重复请求以幂等键处理，并发冲突展示保留输入的修订提示。

验收与测试：原导入请求不含日期仍成功；新导入与日期记录同成同败；月份不进入精确周统计；修改日期不改变快照哈希、完成事件、评分行或偏好／补给行为。测试日期跨时区时系统时刻与用户自然日期的不同处理。

完成条件：日期模型和用户入口闭环，原导入及反馈链路保持兼容，迁移回滚到原 head 后原归档仍可读取。

### R1-03：事实统计与回顾概览（已完成）

**交付**：“归档 → 阅读回顾”可查看本周、本月、全部历史的实时事实概览及对应明细。

工作项：

- 实现第 3 节指标，首页优先展示篇数、补录、覆盖率、反馈变化与缺失口径。

## 8. 事务、一致性与规模

### 8.1 一份报告对应一次一致的输入快照

报告生成遵守以下顺序：

1. 短写事务预约 `ui.review` 任务并保存规范化请求。
2. 显式开启只读事务，固定截止时刻并批量读取源数据；注意当前 sqlite3 legacy 模式下，仅 `Session.begin()`／SELECT 不保证实际读事务已开启，需要沿用项目已验证的显式事务方式。
3. 将已读取内容转换为不可变分析数据后关闭读事务。事务外汇总、渲染和计算内容指纹。
4. 新开 `BEGIN IMMEDIATE` 短写事务，校验运行未取消、请求幂等和版本约束，原子保存完整报告与结果引用。

不能在步骤 2 的同一个事务里升级为写事务。统计读取期间发生的新反馈留给下一份报告；即使提交时间晚于该反馈，报告仍表明自己的采集截止。报告成功和运行终态需防止一边成功一边显示失败，重试优先查运行 ID 对应的完整快照。

日期和资产写入同样在拿到写锁后做预期版本检查和短写，不在事务中做页面渲染、模型计算或大规模统计。

### 8.2 保持有界，不做提前优化

- 投影以字段为单位批量读取，事实统计无需载入所有摘要及备注全文；只在用户查看相关来源时读取正文。
- 固定批次遍历，整次读取处于同一真实只读快照，按稳定主键分页；不能跨多个独立事务拼出“半旧半新”的报告。
- 第一阶段不建立另一份长期可变的统计缓存；保存报告是不可变结果，实时概览从源记录计算，降低缓存失效复杂度。
- 首先用 1,000 篇归档及多次修订的固定样例检查查询形态、内存与取消响应，记录本机结果；再用 10,000 篇做发布前规模观察。不能只拿几篇样本承诺全历史能力。
- 如达到明显长耗时，进度按读取批次更新，停止在批次边界生效；不能通过偷偷截断文献数来维持速度。

### 实际交付与口径修正

- “归档 → 阅读回顾”共用本周／本月／全部历史／已保存回顾／手工资产次级入口，另有统一导出选择。全部历史列出全部归档来源、日／月／未知精度及当前资产；按时期检索、明细分页和回到论文后的返回链接保留上下文。
- 页面明细不再截到 1,000 条；JSON 的明细上限仍是显式展示限制，指标保持全量。主题筛选携带分类版本，保存报告沿用同一主题范围。
- 页面和 JSON 共用事实采集服务，论文、反馈、日期和资产活动使用同一个真实 SQLite 只读快照及排他知识截止。报告使用开始采集的确定时刻；重复保存未变输入保留原快照截止，不因墙钟推进重复落库。报告成功状态和结果引用随快照原子提交，读取批次之间可停止。
- 旧报告变化提示按原时区、周期和模式重新选择有效事实。当时记录不会纳入截止后的更正；现在重新回顾可显示后来更正。周期外无关新阅读、全库库存数字单独变化不会把旧报告标为失效，保存正文与导出始终不变。
- 默认事实导出剥离私人反馈备注、资产标题与正文；个人完整 JSON 副本显式确认后含反馈备注、日期声明、资产全部版本与来源。报告个人副本仅取冻结正文。个人 JSON 是阅读资料副本，当前没有自动导入恢复入口；工作区恢复使用完整数据库或目录备份。
- 修正资产新建错误时只留短草稿、冲突草稿可能重复、删除报告复选框位于表单外等问题。资产正文与 HTML／指令均只作转义文本；若删除来源但保留含正文报告，详情明确仍存私人副本。
- 日期自然日边界兼容夏令时；月精度且完全不与周期相交的记录不再误列入本周相关月份。
