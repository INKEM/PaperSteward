# ADR 0003：G2 的版本化审阅证据

- 状态：采纳（2026-10-21，P2-S3）。
- 上下文：P1 Tag 没有边界案例字段；种子导入属于 S4。G2 必须绑定 G1 档案、种子标注、
  分类法正文和用户看过的影响预览，不能接受外部 `passed=true`。
- 决策：分类法正文仍是事实源，不改 Tag/Taxonomy/PaperTag schema；边界规则用
  重复的 `- 边界：案例；判为：Txx；理由：说明` 行表达，审阅时从正文读取。
  这不是新增可独立编辑的边界案例库，不向 P1 实体追加字段。
- 新增 `onboarding.taxonomy.drafted` 事件，在追加分类法版本的同一事务保存 G1
  事件/档案版本/hash、完整种子标注清单、样本性质和 base_version。清单中的 null
  标注仍计入覆盖率分母；不导入 Paper、不调用模型，合成样本显式标为“仅流程验证”。
- G2 前重算报告，检查正文/hash、标签缓存、档案状态/版本/hash 和审阅 hash；G2
  事件以可选 evidence_json 保存证据引用、报告 hash 和完整审阅快照。扩展为事件 JSON 合法追加，
  不新增数据库字段或依赖，因此无迁移，head 保持 0003。
- 替代：只信客户端百分比不可审计；把状态塞进 Profile/Config 混淆职责；新边界库
  表在本阶段没有独立编辑/检索需求，增加无用迁移。S4 需要种子库时另建迁移。
- 影响预览：列出种子分布/移动、边界变化、规则变化及既有未读队列待复核项，不写
  论文标签/桶/分数。P1 PaperTag 缺少 taxonomy_id，队列匹配只能据版本/标签代码，
  明示此限制，不声称已精确计算或执行重新分类。
- 回滚：回退 S3 代码不删除文档/事件；若运行旧枚举代码，需恢复 S3 前数据库备份。
  已过 G2 的状态不自动撤回。未来需独立边界案例库时新增实体/迁移，不改变此契约。
