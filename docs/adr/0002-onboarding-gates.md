# ADR 0002：独立初始化状态与统一执行门禁

- 状态：采纳（2026-10-21，P2-S1）。
- 上下文：P1 冻结 Profile/Taxonomy 等模型；P2 需要持久化 G1–G4 与确认事件，且
  不能通过文献仓储的直接写入绕过 G4。
- 决策：新增 singleton onboarding 表与 0003 可逆迁移，不修改既有表字段。纯领域
  状态机定义顺序；服务以 revision 条件更新及同事务事件记录确认；仓储执行入口
  共用 ACTIVE 校验。事件枚举只追加。已有 P1 表/schema/枚举值继续兼容，冻结测试
  改为验证 P1 契约子集，允许按迁移追加 P2 表。
- 证据边界：状态机不替代文档/覆盖率/校准/试运行校验。confirm_gate 必须由可信
  业务服务传入证据校验器；S2–S5 逐步接入，S1 不暴露外部通用确认接口。
- 替代：塞入 Profile/Config 会混淆版本与流程；只记内存状态无法跨重启守门；
  只在路由检查会遗漏 CLI/任务入口。
- 影响：G4 前仓储入队/推送/归档由允许写入变为明确拒绝；旧库 upgrade 后须完成
  初始化才能执行这些操作，已有文献/档案不回填、不删除。无新增依赖或网络面。
- 回滚：停止应用，降级到兼容代码并执行 `alembic downgrade 0002`；仅移除初始化
  状态表，既有领域表与审计事件保留。旧代码不认识新增事件类型，因此有 P2 事件的
  数据库不得直接交给旧枚举读取；应先备份，恢复 P2 前备份才是完整应用回滚。
