# ADR0016：P6 日报、投递与阅读冻结边界

状态：采纳；2026-10-22。

日报按选定runtime时区自然日唯一，保存结构化Digest、内容hash与完整卡片解释。
投递按(日报日期,渠道)唯一。先在独立事务提交投递预约，再执行外部I/O，最后事务确认。
SMTP异常或进程崩溃留下uncertain/reserved，不自动重试；Message-ID稳定但不宣称SMTP
支持exactly-once。文件投递使用原子不覆盖创建、0600，相同内容可恢复确认。
文件成功不依赖邮件成功。发送前再次校验G4、暂停/安静、日期和渠道；正文不含阅读备注。
SMTP支持TLS、SecretStr密码，错误只保留固定信息；新增runtime smtp选项保留旧JSON/hash。

动作携带客户端request_id；事件ID由请求ID确定，同请求同内容复用，冲突拒绝。
状态沿用P1边：queued→pushed→reading→done→archived；用户主动读队列亦保留这些边，
事件标记用户阅读而非真实渠道送达。skip回queued，snooze到期经显式恢复再评分。
不扩张状态机，不把校准标注当阅读，不允许从needs_review等状态完成归档。

归档扩展既有archive_snapshot，以新增JSON列保存完整阅读时内容；不更改P1字段语义。
初始主观反馈冻结，修订仅追加Rating和事件，读取展示最新反馈及历史；不覆盖旧快照。
P5反馈读取优先使用阅读时作者/venue/标签，避免当前元数据漂移影响未来U。
周任务复用P5算术，以Run报告保存周截止和质量检查，不引入第二套偏好公式。

UI使用本地HTML和HTMX薄层（无Node/Jinja依赖）；表单调用同一动作服务，禁跨域变更，
所有不可信文本转义，URL仅http(s)。不提供删除归档/重新绑定权重等P7/P8能力。

无新增Python运行依赖；标准库渲染/SMTP代替模板库/邮件库，降低体积及供应链面。
回滚：停止投递并备份；0010→0009去掉归档内容列，0009→0008删除日报/投递表；
状态/事件/Rating不会自动撤销，完整撤销须恢复备份，uncertain投递必须人工核对。
