# 专项开发方案：持久阅读队列与手动挖掘

> 状态：代码、文档与自动验收已完成，浏览器走查通过；Docker 重建受本机权限阻塞。本文独立记录本专项，不并入 `docs/roadmap.md`。

## 背景

当前产品仍以“每日日报”为中心：同步 / 处理完成后，需要再执行“生成今日日报”，由日报创建当日评分快照、把论文转为可读队列，并固化成当天不可变的阅读清单。由此产生三个问题：

- 同一天多次挖掘时，已生成的日报不会纳入新论文；
- 用户必须先“生成日报”才能看到可读队列；
- 每天必须做一次批次决策，不符合“先囤着、有空再读”的使用方式。

本方案把产品改为：

```text
手动挖掘（可重复） → 持久阅读队列（长期存在） → 随时阅读
```

优先级排序只是参考，不是每日配额；每周阅读容量只作为软建议。

## 与既有改造的边界

- 已实现的“移除人工审核、运行进度、自动归类”继续保留；
- 本方案只改变**挖掘动作、队列生命周期、日报/推送地位与阅读节奏**；
- 不修改初始化向导、模型设置、分类/摘要生成流程；
- 不把本方案追加到现有路线图文档，单独验收、单独回滚。

## 产品决策

1. **不再有每日定时处理/日报/推送**：挖掘完全由用户手动发起；不做每日自动任务。
2. **合并挖掘动作**：一次“挖掘新论文”完成采集 → 去重/筛选 → 摘要/分类/评分 → 刷新队列；不需要再点“生成日报”。
3. **队列持久化**：所有处理完成且合格的论文进入长期阅读队列，不按日期切分。
4. **同一天可多次挖掘**：每次只追加新论文；已存在的论文幂等跳过；不锁定当天内容。
5. **优先级只是参考**：按 `rank_score` 排序展示全部队列，不按每日容量/配额隐藏；容量只显示建议。
6. **日报降级**：核心流程不再生成日报；历史日报/归档保留只读。若未来需要导出，另立“导出阅读清单”需求，不恢复每日调度。
7. **移除日期式延后**：去掉 `snooze` 的 3/7/14 天与 `skip` 的固定延期；不做无日期的隐藏列表。队列里放着就是“以后读”，只有完成、不感兴趣等行动。
8. **一次只跑一个挖掘任务**：避免重复点击静默排队；完成后可立即再次挖掘。
9. **旧数据兼容**：历史 `SNOOZED` 论文恢复为 `QUEUED`；历史日报/投递/归档只读保留。

## 一、挖掘与队列流程

### 挖掘动作

一次 `ui.sync` 运行的阶段改为：

```text
排队 → 采集 → 处理 → 刷新队列 → 完成
```

- 采集完成后显示新增/已存在/去重数量；
- 处理完成后显示处理数、自动归类数、特殊桶数、跳过无摘要数；
- 最后调用新的 `refresh_queue(session, now)` 生成/刷新当日评分快照，把合格论文转为 `queued`；
- 不再调用 `create_digest`；
- 队列刷新失败算失败；无合格候选不算失败，显示“暂无合格候选”。

### 队列读取

- 新增 `read_backlog(session, now, limit, offset, filters)`：
  - 读取 `queued / pushed / reading` 等未完成状态；
  - 每篇取**最新可用评分快照**，不要求快照日期等于今天；
  - 按 `rank_score` 排序，展示全部；`explain_score` 同样取最新快照。
- 保留按日期读取历史队列的能力给报表/排查，但首页不再依赖单日快照。
- 优先级刷新：
  - 每次挖掘完成自动刷新；
  - 队列页提供“刷新排序”按钮（本地计算，不调用模型）；
  - 长期不挖掘时，页面明确显示“排序基于 X 月 X 日快照”，避免误以为实时。

### 状态与行动

- `QUEUED` 语义改为“在阅读队列中”，不再表示“今天被日报选中”；
- `PUSHED` 仅在存在外部投递时使用，普通队列不依赖；
- 移除阅读页的 `snooze`、`skip` 操作与 API/CLI 字段：
  - 保留 `done`（完成并记录阅读）、`reject`（不感兴趣）、`score`/`note`（完成后的修订）；
  - 队列里不读的论文保持 `queued`，不需要任何“延期”动作；
- 升级迁移：`SNOOZED` 状态论文恢复为 `QUEUED`；历史 snooze/skip 事件保留审计，不再产生新事件。

## 二、日报与调度退出核心

- 从今日页/导航移除“生成今日日报”按钮与日报指标；
- 不再从 UI 创建新的 digest；
- 现有 `digest`、`delivery`、archive 数据保持只读，历史日报页面可保留；
- CLI 的 digest/邮件能力标记为高级/遗留，不进入主流程；如确认不再需要，后续单独删除；
- 新初始化的运行参数不再要求 `push_time`、`quiet_start`、`quiet_end`、`paused`、`channel`：
  - 新确认只写入时区、目标占比、外部数据授权等必要字段；
  - 旧工作区的旧字段继续可读，但不参与阻止手动挖掘/阅读；
  - 不新增自动调度器，也不保留“到点才能运行”的限制。

## 三、页面与交互

### 首页（原“今日”）

- 标题改为“阅读队列”；
- 顶部：当前任务卡片（挖掘进度）、上一次挖掘摘要、队列总数；
- 主按钮：**挖掘新论文**（可重复执行）；
- 队列列表：全部未完成论文，按优先级排序；显示标签、摘要、排名、评分、原文/PDF链接；
- 筛选：标签、优先级范围、是否已读/未读；
- 不显示“今日 7 篇”限制；每周容量只显示“按你的容量，今天建议先看 N 篇”作为提示；
- 初始设置完成后直接进入队列，提示“点击挖掘新论文开始”。

### 运行页

沿用已实现的进度页，但步骤改为 `采集 → 处理 → 刷新队列 → 完成`：

- 显示采集数量、处理 `5 / 9`、当前论文、已用时；
- 完成后显示“新增 3 篇，已存在 10 篇；队列共 23 篇”；
- 失败保留已完成数据，可直接重试；
- 不显示“生成日报”阶段。

### 多次挖掘

- 队列页可反复点击挖掘；
- 有任务运行时按钮禁用，完成后恢复；
- 每次完成后高亮“本次新增”的条目；
- 同一论文不会重复入队；
- 新论文按优先级插入现有排序，不打乱已读/已完成状态。

## 四、数据与兼容

- 新增队列刷新服务，不复用“日报即刷新”的旧路径；
- `read_backlog` 读取每篇最新快照；保留 `read_queue(day)` 供历史/报表使用；
- 迁移 `0018`（或下一个可用版本）：`paper.status='snoozed' → 'queued'`，清空活动 snooze 日期依赖；
- 移除 `Action.kind` 中的 `snooze`/`skip` 及对应 UI/CLI/测试；
- 新 `RuntimeParameters` 写入可选字段；旧记录保持可读；
- 不删除 digest/archive 表与既有数据；
- 不新增后台调度、定时器或每日任务。

## 五、测试与验收

- 同一天连续三次挖掘：队列只追加新论文，已存在论文不重复；
- 挖掘完成即可在队列看到论文，不需要生成日报；
- 队列按最新快照排序；旧快照日期显示正确；
- 无候选时运行成功但提示“暂无合格候选”；
- 运行中重复点击被禁用/服务端 409；
- 队列中选择完成/不感兴趣正常，且没有 snooze/skip 入口；
- 旧 `SNOOZED` 论文升级后出现在队列；
- 不再自动生成 digest；历史日报仍可打开；
- 初始化后首页是队列，不出现“生成今日日报”必选步骤；
- `make check`、`make e2e`、迁移检查和浏览器手工走查通过。

## 六、风险与回滚

- **队列膨胀**：全部展示可能很长；用标签/分数筛选和分页，不靠隐藏。
- **排序过期**：长期不挖掘时评分会旧；显示快照日期并提供手动刷新。
- **日报/邮件能力退化**：历史数据保留，但不再自动生成；如需要导出另立需求。
- **旧 snoozed 数据**：迁移到 queued 后可能突然出现在队列；这是预期行为，需在升级说明中提示。
- **回滚**：代码回滚可恢复日报与 snooze，但已迁移的 snoozed 状态不会自动回退；需要旧行为时恢复操作前备份。

## 七、实施顺序

1. 队列服务：`refresh_queue`、`read_backlog`、最新快照排序与解释。
2. 挖掘流程：合并阶段、移除 digest 调用、无候选处理、运行摘要。
3. 阅读行动与迁移：移除 snooze/skip、SNOOZED→QUEUED、runtime 参数简化。
4. UI：队列首页、挖掘按钮、运行进度、筛选、空态与多次挖掘反馈。
5. 测试、文档、CHANGELOG、Docker/浏览器验收。

## 九、挖掘管线改造：Agent 检索规划、分层提速与保底入队（2026-10-24）

针对"检索词手填不灵活、挖掘慢、挖 10 篇只剩 1 篇入队"三个问题的一次性改造：

- **Agent 检索规划**：首页表单移除必填检索词，改为可选「本次关注点」与「期望入队篇数」。
  每次挖掘由 `query_planning/v1` prompt 综合研究档案、近 8 周已读评分历史、队列各主标签
  覆盖与关注点生成 4–8 条互补检索式（prompt 内注入布尔检索语法知识），运行报告列出全部
  检索式与理由；模型失败或输出无效时退回 `generate_queries` 档案确定性展开并标注兜底。
- **分层处理提速**：处理拆为初筛（仅相关度评估）与深处理（摘要/分类/特殊桶）；按相关度
  降序逐波深处理，注定低于门槛的论文不再消耗后三次模型调用；线程池并行模型调用
  （`llm_concurrency`，默认 4）；`llm_cache` 表（迁移 0019）按 model+prompt+input_hash
  缓存通过校验的输出，重复挖掘同一论文不再重复付费；SQLite 文件库启用 WAL，worker 任务
  拆为"只读上下文 → 事务外模型计算 → BEGIN IMMEDIATE 短写落库"，消除并行读写升级死锁。
- **保底入队**：评分配置 gates 新增 `min_queue_yield`（默认 5）与
  `quota_fill_relevance_floor`（默认 40）。正常门槛下不足时最多追加两轮检索规划
  （把已用检索式与缺口反馈给 Agent 换角度）；候选耗尽后仅豁免 `below_relevance_gate`
  这一个理由、按相关度降序补足到下限，填充论文的快照 reasons 带 `quota_fill` 标记，
  读取侧（队列/长期队列/评分解释）识别该标记豁免门槛；其余淘汰理由仍一票否决，
  全部候选低于下限则如实报告缺口（宁缺毋滥）。
- 运行报告新增漏斗：各轮检索式及理由 → 初筛候选 → 深处理篇数 → 本次入队/期望、
  保底填充篇数与缺口说明。
- `make check`：899 项通过；`make e2e`：3 项通过；`alembic upgrade→downgrade→upgrade`
  （0019）通过。
