# 快速开始

目标是在浏览器里完成一次完整设置：连接模型 → 丢材料 → 审阅 Agent 生成的研究档案与分类标签 → 确认 → 去阅读队列挖掘。全程不需要编辑 `.env`。

需要：一个 OpenAI 兼容的模型服务（地址、密钥、模型名），以及能访问文献来源的网络。安装与真实论文处理耗时取决于网络和模型服务。

## 安装并启动

Docker：

```bash
git clone https://github.com/INKEM/PaperSteward.git
cd PaperSteward
./scripts/docker-up.sh
```

该脚本使用额外的 host 网络构建配置和 legacy builder，避免部分主机 Docker bridge
无法访问 PyPI；普通环境也可直接用 `docker compose up --build`。

打开 [首次设置](http://127.0.0.1:8000/ui/setup)。再次启动用 `docker compose up`，停止用 `docker compose down`，命名卷会保留数据。不要用 `down -v` 清理正在使用的数据。

Python 3.11+，可选 pipx：

```bash
pipx install .
papersteward start --data-dir ./var
```

或虚拟环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/papersteward start --data-dir ./var
```

已下载 wheel 时，把 `.` 换成 wheel 路径。wheel 自带迁移资源，可在仓库外运行；当前不假设 PyPI 已发布。源码贡献环境也支持 `make bootstrap` / `make start`。

## 浏览器首次设置

### 第一步：连接模型

在设置页填写 OpenAI 兼容 API 根地址、密钥和模型名：

| 服务 | API 地址示例 | 模型名示例 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 本机 Ollama | `http://127.0.0.1:11434/v1` | 你拉取的模型名 |

点 **测试连接** 会发起一次很小的真实请求；失败时按提示检查地址、密钥与网络。保存后配置进入本机数据库，**保存即表示同意将论文标题、摘要及任务所需的研究方向和分类规则发送给该服务**；生成草案时还会发送研究材料、修改意见和上一版草案。之后不需要每次同步再授权，也不需要重启。

### 第二步：上传材料

粘贴或上传 `.md` / `.txt`，可以分多次添加。材料越具体，草案越贴近你的方向：

- 个人主页的研究简介、研究计划、开题报告
- 代表性论文摘要或综述的引言
- 已有笔记、基金申请书中的研究内容

单份表单上限 512 KiB；多份材料合并后超过模型上下文时会截断并提示拆分。

### 第三步：审阅、提意见、确认

点 **生成草案**。页面原地显示生成进度，完成后自动变为审阅界面，可以：

- 切换 **渲染视图 / Markdown 源码**
- 查看与上一版的差异
- 在意见框里写自然语言修改要求，再生成一版

生成期间想改材料？点 **停止任务** 即可回到上一步，已完成的数据保留；停止是唯一的回退方式，页面只往前推进。

示例意见：

```text
方向太窄，把“多模态检索”也加进来。
不要子方向 S3，把它的关键词并入 S1。
更重视可复现评测，减少纯应用论文的权重。
```

满意后勾选确认，点 **确认，开始使用**。系统会把当前档案与分类标签的版本和 hash 绑定到确认记录，并写入默认运行参数（推送时间 08:00、当前时区、主标签目标占比等）。

## 开始使用

确认后进入阅读队列，点 **挖掘新论文**。不需要填写检索词：Agent 会综合你的研究档案、近几周的已读评分历史和当前队列覆盖情况，自动生成多条互补检索式，并在运行报告里列出所用检索式与理由。可以选填一句「本次关注点」临时引导方向；来源可选 arXiv、OpenAlex 或 Semantic Scholar；「期望入队篇数」决定本次挖掘的目标（正常门槛不足时会继续扩查，仍不足才降门槛补足并明确标注）。

日常顺序：

1. **挖掘新论文**（可在同一天多次执行）
2. 在长期阅读队列随时阅读，完成并记录评分、备注；不关注的论文标为不感兴趣

系统之外已经读过的论文不需要走挖掘流程：在 **归档** 页点「导入已读论文」，粘贴 DOI、arXiv ID 或论文链接（可留空手动填写），附上 1–5 的评分与备注即可直接进入归档。导入的论文不会再被挖掘重复处理，评分照常参与你的阅读偏好画像与挖掘规划。

跑完第一次后，长期队列和阅读归档就会按你的研究方向逐步积累。

## 阅读回顾与手工资产

从 **归档 → 阅读回顾** 进入。本周、本月、全部历史、已保存回顾和手工资产都在这一个入口下，无需模型连接即可使用已激活工作区中的记录。

1. 在导入确认或归档详情中选填实际阅读日期；只记得月份就选月份，也可明确清除为未知。导入时间与阅读时间分别保留，旧论文不会因今天补录就被算作今天新读。
2. 选择周、月或自选日期，按归档时主标签及分类版本筛选。默认“当时记录”按历史周期结束时已知的数据回顾；“现在重新回顾”可纳入后来补录、更正，并注明后补阅读。月精度不会分配到具体某周。
3. 实时概览显示“尚未保存”。点击 **把当前筛选保存为回顾报告**，等待“读取记录 → 汇总事实 → 保存回顾”，即可打开冻结快照、比较同系列版本。系列区分周期、主题及分类版本、时区、模式和统计口径，超过 50 份可翻页。报告不会自动生成；重复保存相同实质输入沿用已有快照，范围外变化和库存数字变化不另建版本。
4. 从归档详情记录收获或问题，至少关联一篇已读文献。可在手工资产中按类型、状态、来源论文和关键词找回，修订内容、关闭或重开问题；修订只改文本时来源及其引用的反馈版本原样保留，历史版本可逐版打开查看当时的正文与来源。资产整理不会增加已读篇数。
5. 打开 **导出副本**：默认事实分享副本不含私人备注、资产标题及正文；个人完整副本须勾选原文说明。全部历史的个人副本为 JSON，包含反馈备注、日期修订、资产全部版本及来源。报告个人副本只包含该报告已保存的原文，不补入最新资产版本。

全部历史包含未知阅读日期的归档，列出来源、日期完整性和当前资产；这里不输出长期偏好或能力判断。删除资产前会列出全部含私人副本（标题/正文）的报告，可勾选一并删除，或对单份报告「另存脱敏版本」；本地下载文件和备份须自行保管。

专题中的资产按活动发生时的来源版本归属，至少一篇来源匹配才入选；跨主题资产只计一次并标明来源，显示本范围内的版本。更换来源后的最新版本不会替换旧报告引用。旧报告仍可阅读、导出；范围或统计口径无法核实时显示未知，不能直接比较，请选择明确范围重新保存。

## 常见问题

- 没有模型 key：无法生成草案或处理论文；已激活工作区可离线浏览已有数据、使用事实回顾、手工资产与导出。
- 旧版 `.env` 里已有模型配置：升级后到 **设置** 页保存一次即可；旧工作区已确认的档案不会丢失。
- 设置到一半退出：材料和已生成草案会保留，回到首次设置页继续。
- 想重新测试或换研究方向：浏览器顶栏的工作区下拉可新建独立工作区（切换即换方向），管理页可删除不用的旧工作区；只想清空重来时，设置页可重置当前工作区，自动备份后重新走首次设置，可选择保留模型连接。
