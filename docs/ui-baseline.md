# UI 读路径性能基线（UXR-24）

日期：2026-10-24 · 分支 `refactor/quality-experience`（批次 G 完成）· 本机环境（SQLite / TestClient,无网络）

## 复现

```bash
.venv/bin/python scripts/perf_baseline.py --papers 50   # 或 200；JSON 写入 var/perf/
```

脚本种子 N 篇可入队论文后计量各读路径的 SQL 条数与墙钟耗时；同参数两次运行
`ui_queue_page` 耗时约 85–172 ms（波动来自冷热缓存），对比改造效果时请同机连跑取中位。

## 本机基线（批次 G 记录）

| 路径 | 50 篇 | 200 篇 | SQL |
|---|---|---|---|
| 刷新排序（首次，含快照创建+入队） | ~300 ms | 579 ms | 2857 |
| `read_backlog`（前 50） | ~30 ms | 29 ms | 19 |
| **/ui/queue 整页** | 85–88 ms | 166–172 ms | 168 |
| **/ui/archive 整页** | 5 ms | 5 ms | 4 |
| **/ui/views 整页** | 18 ms | 37–41 ms | 20 |

## 判读

- 队列页 200 篇约 170 ms、SQL 168 条——与此前提速记录（500 篇约 0.3 s）一致量级；
  上一轮基线中 dashboard 每卡片重复加载分类法的问题已由批量取齐修复。
- 归档页 SQL 仅 4 条（列表逐条读快照是主要成本，当前样本 1 条归档；200+ 归档时需再测）。
- 排序视图随候选数线性增长（预览读取全量 backlog），200 篇约 40 ms，可接受。
