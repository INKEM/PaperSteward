## 2. 已完成且本轮得到支持的能力

- 归档入口下已提供周、月、全部历史、保存报告、手工资产及导出选择。
- 系统阅读与外部补录区分；日／月／未知阅读时间独立于冻结归档；历史模式与现在重新回顾有不同的知识截止。
- 反馈清除和修订不重复计入阅读篇数；旧报告及其导出保持冻结，原始归档不被日期修订覆盖。
- 无模型配置、无外网时可以完成事实回顾、保存、反馈修订和手工问题整理。
- 报告生成复用当前工作区任务、支持停止与重试；现有样例验证无半份报告及同库／跨库隔离。
- 默认分享导出剥离反馈备注和资产标题／正文；显式个人副本可以包含私人内容。

这些能力构成后续开发基础，但不能覆盖下面未被原测试捕获的范围、来源和生命周期问题。

## 3. 必须纳入返工的 6 组问题

优先级约定：P1 为进入第二阶段模型分析前必须修复的正确性／隐私／来源问题；P2 为应随前置批次修复的功能完整性问题。未发现影响现有挖掘与队列主流程的 P0 故障。

### F01 · P1：专题筛选未约束资产活动和资产引用

**复现**：分别建立 T01、T02 两篇归档，只为 T02 建一个问题；生成 T01 专题周报。文献阅读量为 1，资产活动与报告引用却仍包含 T02 的问题各 1 条。

**原因**：`build_overview` 只筛选 `projection.papers`，资产事件没有关联专题来源；`prepare_report` 仅按活动周期筛资产，没有按主题过滤。见 [aggregate.py](../src/papersteward/reading/insights/aggregate.py)、[reports.py](../src/papersteward/reading/insights/reports.py)。

**影响**：专题事实口径不一致；选入资产正文时，不相关主题的私人内容也可能混进报告。此处是同工作区的范围串用，不是跨工作区泄漏。

**修复验收**：统一文献、资产活动、资产引用的范围，按活动发生时的资产版本来源判定归属；跨主题资产以“至少一条来源匹配”入选一次，并披露跨主题来源。追加更换来源、历史截止、混合来源与勾选正文的回归用例。

**落实批次**：R2-00A；探针 `A01_topic_scope`。

### F02 · P2：范围外记录改变专题报告指纹

**复现**：保存 T01 的全部历史专题结果后，仅增加一篇 T02 文献。T01 有效事实没有变化，但输入指纹变化，会保存一份实质相同的新报告。

**原因**：`report_fingerprint` 使用完整 `projection.papers`，而正文统计使用过滤后的范围。见 [reports.py](../src/papersteward/reading/insights/reports.py)。

**影响**：范围、变化提示和去重使用不同输入集合，造成无意义版本；第二阶段若沿用此指纹，将重复触发分析和费用。

**修复验收**：建立统一的有效输入清单供统计、指纹、变化提示及后续分析使用；范围外新增／修订不得改变专题指纹，范围内来源、反馈版本及周期结束语义的变化仍须被识别。

**落实批次**：R2-00A；探针 `A02_scoped_fingerprint`。

### F03 · P2：报告系列混入其他范围，且被全局前 50 条截断

**复现**：同一周、同一模式分别保存 T01、T02 和 UTC 时区报告，系列查询将三者归在一起；再插入 51 份较新的其他周期报告，原系列返回 0 条。

**原因**：`list_series_reports` 先取全局最近 50 条，再按类型／日期／模式过滤，遗漏主题和时区。保存行也没有独立、完整的规范化范围，部分还依赖运行记录还原。见 [reports.py](../src/papersteward/reading/insights/reports.py)、[storage/insights.py](../src/papersteward/storage/insights.py)。

**影响**：用户可能把不同主题或时区造成的差异误认为历史变化；报告积累后旧版本不可达。手工传入 `compare` 也没有校验两份报告是否同系列，需一并补上。

**修复验收**：报告独立保存范围及语义版本，数据库先按系列过滤再分页；比较前校验类型、日期、模式、时区、主题和算法口径。无法可靠还原的旧范围标为未知，不伪装成“全部主题”。旧正文和哈希不重写。

**落实批次**：R2-00A；探针 `A03_report_series`。

### F04 · P1／P2：幂等键未绑定完整请求及目标

**复现一（P1）**：为论文 A 写阅读日期，再对论文 B 使用相同键及日期，返回成功视图，但 B 的版本仍为 0，没有保存声明。

**复现二（P2）**：创建问题后使用相同键、相同类型但不同标题再次提交，服务静默返回旧资产，不拒绝不同请求。资产修订也没有独立的重放回执，只会把成功后的重试当成版本冲突。

**原因**：日期命中比较没有包含论文 ID；资产创建命中只比较 kind，没有比较标题、正文、来源等；见 [timeline.py](../src/papersteward/reading/insights/timeline.py)、[assets.py](../src/papersteward/reading/insights/assets.py)。

**影响**：用户可能收到“保存成功”但自己的输入没有保存；后续“确认候选为资产”若沿用该路径，会丢失用户确认内容。

**修复验收**：键绑定工作区内的操作类型、目标及规范化请求哈希；同键同请求重放原结果，不同请求明确冲突。覆盖跨论文、改正文、改来源、清空字段、成功响应丢失重试及真实双会话并发。兼容旧键不得靠猜测把缺失回执当成新写入。

**落实批次**：R2-00B；探针 `A04_idempotency`。

### F05 · P1：普通页面修订丢失具体反馈来源，历史正文也无法逐版查看

**复现**：创建引用某条具体反馈时间戳的资产，在浏览器修订表单中仅改标题。解析器把来源重新构造成只有论文 ID 的列表，保存后的 `rating_at` 变为 null。

同时，资产详情及 JSON 返回的历史版本只有版本号、时间、标题和状态；旧正文、适用说明及来源保留在数据库，却没有逐版本读取入口。个人完整副本可导出旧数据，不等于浏览器中的历史查阅已完成。

**原因**：`_parse_asset_revision` 不保留具体来源版本；`get_asset_view` 的 history 仅包含 `AssetRevisionSummary`。见 [insights_pages.py](../src/papersteward/api/insights_pages.py)、[assets.py](../src/papersteward/reading/insights/assets.py)。

**影响**：资产与用户判断的联系变弱；无法核对“过去为什么这样认为”。这是第二阶段证据链必须先修好的基础。

**修复验收**：未主动改变来源时保留原有 `paper_id + archive_hash + rating_at`；显式增删来源与文本修订分开处理。增加逐版本详情和来源跳转，旧反馈可定位，不能只跳到最新备注；旧正文和来源不可被新版本替代。为来源消失／校验失败给出明确状态。

**落实批次**：R2-00B；探针 `A05_asset_provenance_history`。

### F06 · P1：删除私人副本的预览遗漏资产标题

**复现**：保存不含资产正文的报告，仍会冻结私人资产标题；删除资产预览只把 `body != null` 的报告列为可一并删除，标题副本不在清理范围。删除后 UI 隐藏旧标题，但报告 JSON／个人导出依然含该标题。

**原因**：`_reports_with_asset` 的私人成分判断只看正文，而 `ReportAssetRef` 始终保存标题；UI 的“来源已移除”不能代表底层副本被删除。见 [assets.py](../src/papersteward/reading/insights/assets.py)、[reports.py](../src/papersteward/reading/insights/reports.py)。

**影响**：删除范围说明不足，用户无法通过现有资产删除流程清理标题中透露的研究计划。默认事实分享仍会剥离标题，但原始详情及个人副本保留，不能因此视为无问题。

**修复验收**：按字段识别私人标题、正文、适用说明及未来衍生内容，预览全部持久副本；允许删除选定报告，或明确保留并告知。旧不可变报告通过删除整份或另存脱敏版本治理，不能暗改正文／哈希。覆盖“只有标题”“空正文”“多个版本”和 JSON／导出／页面三种读取路径。

**落实批次**：R2-00C；探针 `A06_private_title_copies`。
