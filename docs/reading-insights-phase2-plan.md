# 阅读回顾第二阶段：有证据的知识提炼实施计划

> 日期：2026-10-26。状态：R2-00A、R2-00B、R2-00C 已完成并复验，第一阶段六组返工全部关闭；R2-01（§19）、R2-02（§20）、R2-03（§21）已完成并复验；R2-04 及后续批次待实施。原计划与独立复核记录保留，实际交付见 §16–§21。
> 起点：第一阶段基线 `3a351b4`、迁移 head `0023`；[独立复核发现 6 组返工项](reading-insights-phase1-acceptance.md)。
> 对应愿景：[功能设计第二阶段](reading-insights-design.md#第二阶段有证据的知识提炼)。本文将返工、数据与授权基础、知识提炼和验收拆成可独立审阅的交付批次。

## 1. 目标与阶段边界

本阶段交付一条完整流程：**选择材料 → 明确分析用途与去向 → 提炼有来源的候选 → 用户核对／修订 → 保存长期资产 → 在周月回顾及长期记忆中找回。**

完成后应具备：

- 可选的结构化阅读理由，与原评分和备注分别保存，能够解释“为什么给这个评价”。
- 按用户选定材料及用途运行模型辅助分析，私人备注、资产和衍生内容都有独立数据边界。
- 单篇收获、问题、方法候选；跨文献专题、条件对照及证据组候选；用户可查看原材料、改写并保存。
- 长期价值标准与阶段兴趣候选，呈现跨期证据、反例、语境和未知信息，用户可以纠正或停用。
- 含知识整理部分的新版周／月回顾；第一阶段事实统计和历史报告持续可用。

本阶段候选及确认后的画像**仅用于回顾与资产整理**，不输入现有检索规划、偏好分、排序、入队门槛或研究档案。与推荐的联动属于第三阶段；用户确认某条归纳不等于授权系统改研究方向或把私人材料外发。

不新增定时生成、邮件推送、全文 PDF 解析、外部知识库同步、跨工作区汇总、精确能力评分或无人审核的“领域结论”。模型不可用时第一阶段和本阶段的手动整理仍然可用。

## 2. 第一阶段返工必须先完成

本轮已重跑格式、ruff、mypy、1,174 项非 e2e、4 项 e2e 和空库迁移往返，均通过。但补充审计复现了以下缺口，完整证据见[验收报告](reading-insights-phase1-acceptance.md)。

| 编号 | 问题 | 优先级 | 进入第二阶段后的风险 | 前置批次 |
|---|---|---|---|---|
| F01 | 专题未过滤资产事件及引用 | P1 | 不相关材料进入分析、报告和私人正文副本 | R2-00A |
| F02 | 全库投影参与专题指纹 | P2 | 无关改动触发重复分析与费用 | R2-00A |
| F03 | 系列遗漏主题／时区，先全局限 50 再过滤 | P2 | 错把不同研究范围当历史变化，旧版本不可达 | R2-00A |
| F04 | 幂等键没有绑定完整请求及目标 | P1／P2 | 反馈或确认候选时虚报保存，不能可靠重试 | R2-00B |
| F05 | 页面修订丢反馈版本、历史只有摘要 | P1 | 来源链变弱，旧认识无法逐版核查 | R2-00B |
| F06 | 私人副本删除只看正文，遗漏标题 | P1 | 扩大模型分析后无法完整识别／清理衍生内容 | R2-00C |

这三批属于第一阶段返工，不把它们包装成第二阶段新功能。全部完成并复验后，才能开放任何模型辅助阅读分析入口。结构化反馈和授权界面的开发可在分支中准备，但未完成返工前不放行模型调用。

## 3. 总体分批与依赖

| 批次 | 交付 | 可以验收的结果 |
|---|---|---|
| R2-00A（已完成） | 统一范围、快照上下文和报告系列 | 同一范围的事实、资产、指纹和比较一致 |
| R2-00B | 修复请求重放、来源保留及逐版查阅 | 保存不虚报，旧正文与具体反馈来源可核查 |
| R2-00C | 补齐私人字段与派生副本治理 | 标题、正文及引用的保留／删除范围可解释 |
| R2-01 | 可选结构化反馈 | 记录价值理由与使用语境，不增加归档必填项 |
| R2-02 | 材料清单、用途授权及派生来源链 | 分析前可核对材料、端点及范围，撤回有明确效果 |
| R2-03 | 单篇有来源的提炼候选 | 事实／个人判断／模型归纳可区分，材料不足如实显示 |
| R2-04 | 候选核对、方法与证据资产 | 用户可修订确认、关联或合并，避免同义资产反复生成 |
| R2-05 | 跨文献专题与知识版周月回顾 | 比较条件与分歧，报告标明覆盖和限制 |
| R2-06 | 长期记忆与画像候选 | 稳定偏好、近期兴趣与知识资产分别表达，可纠正停用 |
| R2-07 | 发布验收、规模与隐私验证 | 端到端、历史兼容、撤回删除及故障恢复闭环 |

推荐顺序：`00A → 00B → 00C → 01 → 02 → 03 → 04 → 05 → 06 → 07`。其中 03 依赖材料和授权基础，05 依赖已验证的单篇结果和资产来源，06 消费原始反馈与跨期证据，不能只消费一串自动生成的报告摘要。

每批独立检查点，不一次创建全部后续表或 prompt。业务实施开始时建立 `feat/reading-insights-phase2` 分支，按仓库规则保留并排除无关未提交改动。制定计划时未切分支或提交；R2-00A 已在该分支实施。

## 4. 三批前置返工

### R2-00A：统一有效范围与报告身份

**状态：已完成（2026-10-26）**；验证与兼容边界见 §16。

代码落点：`reading/insights/aggregate.py`、`overview.py`、`reports.py`、`storage/insights.py`、`api/insights_pages.py` 和新增范围契约。

工作项：

1. 建立 `AnalysisScope`／有效输入清单：周期、时区、回顾模式、分类版本＋主标签、知识截止、统计算法版本。
2. 先选择有效文献，再按资产**当时版本的来源**选择资产事件及引用；多来源资产至少一条匹配时入选一次，页面标明其跨主题来源。
3. 报告统计、指纹、变化提示和后续材料选择消费同一清单。区分“范围内有效输入”与“仅供说明的全库库存”，后者变动不触发专题新版本。
4. 将规范化请求和范围独立存入报告上下文，不能依赖运行记录永远存在。系列查询先在数据库按完整系列身份过滤再分页；比较接口拒绝不相容的系列。
5. 旧报告通过可核查的运行参数回填上下文；无法还原的字段标为未知。补上下文不改旧正文及哈希，不将缺失主题解释成“全部主题”。

验收：将 F01–F03 的探针改成断言正确结果的正式测试；增加来源跨主题／改来源、分类版本、时区、超过 50 份无关报告、范围外新阅读／新反馈、运行记录缺失等场景。

完成条件：范围一处定义、一致生效；旧报告可读；无关数据不能制造新版本和新模型分析预算。

### R2-00B：可靠保存与来源版本闭环

代码落点：`timeline.py`、`assets.py`、`contracts.py`、相关表单、资产仓储和新写入回执。

工作项：

1. 日期、资产创建／修订／状态操作的幂等键绑定操作、目标及规范化请求哈希；同键同请求重放原结果，不同请求明确冲突。
2. 回执与业务写入同一短事务提交；预期版本检查在写锁内执行，唯一约束兜底，真实并发错误转换为可恢复冲突。
3. 对既有键从首次版本和可核查来源恢复请求信息；无法证明原请求内容时提示冲突，不静默承认新请求成功。
4. 资产文本修订保留未主动更改的 `paper_id + archive_hash + rating_at`；来源增删明确表达，不能因表单只显示论文 ID 就清掉反馈版本。
5. 增加逐资产版本读取入口、历史正文／适用说明／来源页面及具体反馈定位。引用不存在或校验失败时显示原因，不偷偷改指向最新内容。

验收：覆盖相同键用于不同论文、改标题／正文／来源、清除字段、成功响应丢失重试、两写会话并发、只改标题保留反馈引用、历史版本正文可查看。

完成条件：F04／F05 关闭；候选确认可以可靠复用资产写入，而不会把输入丢失误判为用户已经确认。

### R2-00C：私人字段与派生副本清理

代码落点：`assets.py` 删除预览、报告导出、页面删除流程、报告契约及引用索引。

工作项：

1. 私人成分包括用户标题、正文、适用说明、反馈片段和后续模型推测；不能只根据 `body` 是否为空判断是否存在私人副本。
2. 删除预览列出字段类别、来源版本、报告／导出持久副本及用户可选动作。无正文但有私人标题的报告也能被选中清理。
3. 不可变报告通过删除整份或另存脱敏版本处理；保留时明确原副本仍存在，不能用 UI 隐藏代替实际删除。
4. 建立来源到派生对象的可查询索引或清单，供 R2-02 的授权撤回及以后模型结果清理复用；先覆盖已有报告和资产，后续类型逐批加入。
5. 事实导出默认排除所有私人字段；个人副本显式选择后可保留。数据库／目录备份和已下载文件不声称能够自动收回。

验收：仅标题副本、多版本、多报告、清理与保留、原始 JSON／页面／导出一致、删除事务中断回滚。F06 关闭后重新复核第一阶段。

完成条件：完成第一阶段返工复验记录；存在私人副本时，用户能知道在哪里以及怎样处理。

## 5. R2-01：可选结构化反馈

**用户交付**：原来的评分＋备注仍可直接归档；愿意补充时，可以用少量选项说明价值和语境。

新增反馈维度：

- 价值来源：方法可复用、帮助理解、改变认识、提供论据、带来研究想法、可用于当前任务。
- 价值有限的原因：当前任务不适合、内容已知、证据存疑、适用条件不满足、暂时看不懂。
- 语境：可选任务／专题说明、阶段性适用范围；不为此新增完整项目管理系统。
- 可选一句收获、疑问或实际使用结果；这些自由文本都是私人材料，后续分析默认不发送。

实现安排：

1. 独立 `StructuredFeedbackRevision` 契约与追加式存储，保存记录时间、来源论文及可选关联的具体评分版本；采用 R2-00B 的幂等和版本机制。
2. 不把这些理由塞进 `Rating.note`，不改 `Action.done` 的必填要求，不扩展现有评分 `Feedback` 为模型判断容器。
3. 关联某条评分的理由保留关联版本；后来改评分不自动把旧理由解释成新评分原因。
4. 页面先给少量常用选项，其余折叠；支持跳过、清除和修订。理由码与显示文案版本化，历史记录可解释。
5. 事实回顾新增结构化反馈覆盖与修改记录，不从总分推导未填维度；同一论文仍只计一个阅读样本。

测试：旧导入／归档请求兼容，低分且“任务无关”不形成质量结论，高分且“帮助理解”不等于支持有效性，空理由不被补成中立，多次修订按知识截止选择。

完成条件：无需模型即可记录与查看理由；现有评分、偏好、补给和检索 prompt 不消费新增文本或推测。

## 6. R2-02：材料清单、用途授权与来源链

**用户交付**：分析前看清使用哪几篇、哪些版本、哪类文本、发送到哪里；可以排除材料、保存适用范围内的持续授权或只授权本次。

### 6.1 材料必须有版本与可用时间

建立 `AnalysisManifest` 和材料引用：

| 材料类型 | 允许依据 | 必须展示的限制 |
|---|---|---|
| 冻结元数据／导入摘要 | 归档内容哈希＋字段路径 | 只有摘要时不能宣称验证全文结论 |
| 既有模型概括／摘录 | 原归档中的模型产物及溯源 | 标为历史模型概括；无法对照原文时不能称作已核验原文证据 |
| 主观评分与结构化理由 | 截止前的具体记录版本 | 用户评价，不是论文客观质量 |
| 备注、个人收获、问题、适用说明 | 用户明确选定的原始版本 | 私人文本，独立授权 |
| 已确认资产／画像 | 具体资产／画像版本及其来源链 | 确认不消除私人属性，也不证明学术结论正确 |
| 用户补充摘录 | 保存的摘录、出处说明及录入时间 | 标明用户提供；没有核对全文时不能自动承诺引文真实 |

不把当前 `PaperRow.abstract` 偷偷当成历史冻结摘要。确需补入新材料时，显式采集保存其版本、来源与当前可用时间；只进入“现在重新回顾”或更晚周期，不倒灌旧报告。首期不抓取 PDF。

清单固定范围、知识截止、材料 ID／版本／哈希、字段、隐私类别、选择／排除原因、实际覆盖篇数和模型任务。统计覆盖全部归档与内容分析覆盖部分文献分别展示。

### 6.2 授权是任务用途和端点的组合

- 增加阅读分析用途授权，独立于既有模型设置 consent；选择本机端点也不自动纳入所有私人文本。
- 绑定当前工作区、用途、规范化端点身份、模型配置版本、材料类别、选择范围及授权版本。地址变化、类别扩大或用途变化须重新说明；既有授权不能被新端点沿用。
- 支持本次及当前工作区持续授权；持续授权覆盖的普通再次生成无需重复弹窗，材料排除规则始终有效。
- 预览令牌短期有效，绑定清单及配置版本；提交时重新核对。发生材料、端点或排除规则变化时提示重新预览，不发送旧界面之外的内容。
- 页面浏览和事实统计不联网。只在显式模型辅助生成时调用批准的端点，不在失败时悄悄换服务、回退环境变量端点或扩大材料。

### 6.3 撤回覆盖整个派生链

原始备注 → 提炼候选 → 方法资产 → 专题综合 → 画像／知识报告，是同一条来源链。任何一步引用私人材料，后续内容保守继承其私人类别；用户确认不会自动把它变成可公开／可发往其他端点的数据。

撤回后停止新派发，取消尚未发送的调用，返回结果在落库前再次校验授权版本；已进入发送状态的请求不能保证收回，界面明确列出在途状态。可以保留本地结果但停用、删除派生副本或另生成脱敏版本；私人数据正文不出现在撤回审计日志里。

实现时将授权校验放到每次实际发送边界，重试和 repair 同样受约束；不要仅在页面按钮上检查，也不要在持有数据库写事务期间等待模型网络响应。

私人分析初版关闭通用 `DatabaseLLMCache`（`cache=None`）。当前通用缓存键只有 model＋prompt＋input_hash，且缺少授权／端点／派生删除索引，不直接用于新私人分析。将来如启用专用缓存，必须先完成相同端点与授权边界、来源索引、过期与清理验收。

测试：未授权／排除材料不进入捕获的 prompt；更换端点、预览过期、任务排队期间撤回、在途返回、repair、重试、缓存命中企图、日志错误脱敏及工作区隔离。用 FakeLLM／本机捕获端点完成，不要求真实私人材料外发。

完成条件：默认关闭私人文本分析，数据去向可核查；仅有既有模型授权时，新私人分析调用次数必须为零。

## 7. R2-03：单篇证据化提炼与任务编排

**用户交付**：从选定论文得到少量“收获／问题／方法”候选，每条都有来源、性质、条件和不确定部分。

代码分层建议新增 `reading/insights/materials.py`、`authorization.py`、`analysis.py`、`evidence.py`，存储与 API 仍分别归对应层。业务调度使用当前工作区 `UIFlowManager` 的新任务类型，不把模型分析混进原 `ui.review` 事实任务。

工作项：

1. 固定已授权材料清单，事务外调用 `LLMGateway.complete_json`；只传最小必要字段，不整库拼接备注。
2. 新增 `reading_reflection/v1` prompt 及严格 schema，输出候选类型、陈述、条件、限制、来源引用和结论性质；“无足够材料”是合法结果。
3. 候选区分论文陈述、用户表达、模型归纳；模型不能给自己生成“用户已确认”状态。
4. 服务端验证材料 ID、版本与字段存在；直接引文须匹配所引材料中的原文范围，页码仅能来自明确保存的出处。仅有已存在 ID 不能证明语义成立，归纳仍待用户核对。
5. 单篇失败不改动事实报告；显示完成／失败／材料不足及覆盖范围，保留有效候选。schema 无效仅按网关规则 repair 一次，失败不从残缺 JSON 猜出资产。
6. 预算包含输入量、调用批数和重试／repair；长材料不能静默截断后声称全部读过。停止在批次及调用边界生效，失败可仅重试未完成材料。
7. 新分析运行、材料清单和结果引用持久化；运行进度只保留计数、状态、成本和对象 ID，不包含私人正文或完整原始模型异常。

最少候选字段：稳定候选 ID、分析批次、材料来源、类型、文本、适用条件、限制、结论性质、核对状态、生成溯源和私人类别。不生成未经校准的置信百分比。

测试：高分综述不推导有效性、低分任务不适配不形成方向排除；伪造来源／页码、指令注入、材料不足、超预算、取消、断网、repair 失败、端点变更和重启。所有新 prompt／schema 明确更新冻结注册表和离线样例。

完成条件：未经用户确认不写入正式资产或长期画像，所有候选可定位到本次真正使用的材料。

## 8. R2-04：候选核对、方法卡与证据组

**用户交付**：候选可以确认、改写、关联已有资产、合并或忽略；资产库新增方法卡及证据组，普通手工收获和问题继续可用。

### 8.1 确认与来源

- 确认页并列候选与实际来源，允许改结论、条件、限制及来源；“确认”表示用户认可个人整理，不等于系统验证论文真实性。
- 确认动作通过 R2-00B 的幂等服务写入资产新版本，并保存候选→决定→资产版本的关系。
- 改写或合并不会丢掉原来源角色；用户新增未提供证据的内容须标为个人判断，不能伪装成原文摘录。
- 忽略、纠正和合并形成可回看的决定；同一来源版本再次分析不得仅换措辞就重复弹出相同候选。新证据发生实质变化时才提示重新审视，并说清变化来源。

### 8.2 新资产结构

| 类型 | 必要内容 | 来源角色 |
|---|---|---|
| 方法卡 | 解决的问题、适用条件、关键做法、限制；资源／数据要求未知时留空 | 描述方法、实际使用反馈、限制说明 |
| 证据组 | 待讨论论点、支持材料、限制／不同结果、研究条件、尚未核实部分 | 支持、限制、不同结果、仅提供背景 |

通过明确迁移扩展资产类型及类型化版本内容，不将结构化方法 JSON 硬塞进原来的自由正文。保留旧资产 API 和展示能力，新增版本契约；旧报告的资产引用和旧资产版本不原地升级。

合并使用稳定目标资产及可追溯的原资产关系；原引用仍能找到当时版本，不能把所有历史指向强行改成新正文。删除和授权撤回通过 R2-02 的派生链处理两边内容。

测试：重复确认只生成一次、并发修订保留输入、旧来源完整、拒绝记忆持久、合并后引用可查、方法／证据类型字段校验与回滚保护、私人标题和衍生内容清理。

完成条件：用户能得到可独立检索、修订、导出的长期资产；候选数增长不能替代真正的资产整理闭环。

## 9. R2-05：跨文献专题与知识版周月回顾

**用户交付**：周报在事实之上提炼本期少量收获和问题；月报直接从原始材料及相关资产形成专题综合，不依赖先生成周报。

工作项：

1. 新增 `reading_synthesis/v1` prompt／schema，输入为获准材料、经校验的单篇结果、用户确认资产及其证据链；统计数字始终由确定性事实层提供。
2. 形成问题—方法—场景的条件对照，指出可能支持、限制和待比较的关系；样本、数据、任务或指标不同不能直接宣布结论冲突。
3. 跨领域迁移或研究机会标为候选联系；“我尚未读到”不能升级为“领域空白”，已有概括不能循环引用来增加证据数量。
4. 回顾范围以当期活动为主，可关联旧文；正文披露全部候选数、实际分析覆盖、缺失材料及未完成部分。新资产归入同一库，不每月复制同义卡。
5. 引入 `reading-insights.report/2` 的知识章节和实际分析上下文；按存储 contract 分派解析，旧 `/1` 报告读取／导出不被新必填字段破坏，未知版本明确报错。
6. 新报告保存固定内容、材料清单和所用资产版本；不能在打开旧报告时补最新模型总结。系列和比较沿用修复后的完整范围与算法语义。
7. 分享副本默认排除私人衍生段落，不只删引号中的原备注；涉及私人材料的整条归纳按来源链判定。个人副本显式选择，并展示包括哪些类别。

测试：未生成周报也能生成月报、部分失败不冒充全量、历史／重新回顾不混淆、旧报告稳定、相似主题不等于矛盾、不同条件并列、私人归纳未显式选择不得进入分享副本。

完成条件：每条综合判断可追到真实材料或用户表达；不牺牲第一阶段统计准确性来换取流畅叙述。

## 10. R2-06：长期研究记忆与画像候选

**用户交付**：“全部历史”增加明确分层的研究记忆；事实、资产、近期兴趣和长期价值标准分别可查，用户可以更正、限于当前任务或停用。

工作项：

1. 新建独立的阅读画像存储，不写入现有已确认的 `ResearchProfile`。候选、确认、修订、停用和需复核各有版本与来源。
2. 先做确定性证据分组和样本说明，再用 `reading_profile_inference/v1` 生成审慎表述。候选至少列出支撑、相反证据、时间范围、任务语境及未覆盖信息。
3. 单篇只能形成兴趣线索。稳定偏好候选的保守展示门槛延续“至少 3 篇不同文献、跨 2 个自然月”，同时检查可核查反馈的时间；一天导入多年旧阅读不能制造多年稳定评价。
4. 阅读日期、反馈形成时间和系统补录时间分开展示；仅有用户回忆的时间标为回溯声明，不冒充当年留下的连续记录。单项目／单次批量集中样本降低结论强度。
5. 对比近期 8 周、此前相同长度窗口与全部历史背景；不以旧画像摘要的重复出现当成新的独立证据，也不因近期没新反馈删除旧资产。
6. 用户能修改措辞、选择“仅本次任务适用”“这不代表偏好”、暂不采用或停用；纠正结果进入下一次分析，不能生成后又覆盖用户修正。
7. 支持按问题、资产类型、关键词及时期找回证据；首期不以词面哈希 embedding 推导知识距离或掌握程度，自然语言检索只作后续可选增强。

测试：单篇高评价、一天批量补录、跨期支持但有强反例、全部样本来自单项目、日期未知、用户纠错、停用后再次分析、来源撤回或删除。检查现有检索 planner 和偏好评分中完全没有新画像内容。

完成条件：画像是可修订的个人研究记忆，不形成自动生效的推荐规则；所有“已确认”状态来自用户动作。

## 11. 存储、契约与迁移策略

实施时按当前主线分配后续迁移编号，从 `0023` 之后追加；本文不预占编号。建议按以下依赖分组建表／变更，不更改已发布迁移：

| 所属批次 | 存储变化 | 关键约束 |
|---|---|---|
| 00A／00B | 报告上下文、写入回执；必要的索引 | 旧正文不变，回执与目标／操作／请求哈希绑定，旧范围不猜测 |
| 00C／02 | 私人派生引用、用途授权及撤回事件、材料清单 | 可按来源版本找出所有副本；审计不保存私人原文 |
| 01 | 结构化反馈版本 | 按知识截止读取，清除语义明确，关联具体评分而非最新评分 |
| 03 | 分析运行结果、候选与材料引用 | 工作区内幂等，源版本不可漂移，部分完成和失效可区分 |
| 04 | 候选决定、资产新类型／类型化版本、合并关系 | 用户确认与模型建议分开；原版本来源保留 |
| 05 | 新报告内容契约及分析引用 | `/1`、`/2` 显式分派，未知版本不静默解析 |
| 06 | 阅读画像条目、版本、证据与用户决定 | 与研究档案分离，状态与适用范围可追溯 |

原始反馈／资产已有不可变版本时，材料清单保存引用与哈希，不再复制整套私人正文；缺少不可变原文的新材料才另存版本。候选与模型输出本身也是持久副本，必须登记在派生链，不能只登记最终确认资产。

SQLite 修改资产类型 CHECK 等旧表结构时必须写迁移，并用已有收获／问题、来源及报告数据验证，防止重建表时因外键级联丢数据。降级遇到无法表示的新类型应明确拒绝或要求先导出处理，不静默变成旧类型；新增表的降级损失范围列入发布说明。

新 LLM 输出 schema 建议三类：`reading_reflection`、`reading_synthesis`、`reading_profile_inference`；对应版本化 prompt。注册到 `schemas/models.py::SCHEMA_MODELS` 和 `llm/prompts.py`，显式更新 `test_p1_freeze.py`、`test_json_schemas.py`、`test_llm_prompts.py`。应用输入／材料／授权契约不因名称相似就注册为 LLM schema。

每次新增迁移同步 `tests/integration/test_migrations.py` 的表／字段和 head 断言，以及 `test_start.py`、`test_workspace_reset.py`、`test_cli.py` 中的版本／doctor 输出。新 ORM 表与正式迁移必须一致，不能只在 `create_all` 测试库中通过。

不改变 P5 `QueueItem`／`ScoreExplanation`／`Exclusion`，不改 scoring.yaml、不新增 embedding 依赖；原评分 golden 必须继续通过。

## 12. 接口、页面和任务拆分

以下为拟新增／扩展面，具体路由在各批次冻结，不能提前宣称已经可用：

| 能力 | 建议服务／页面落点 | 约束 |
|---|---|---|
| 逐版资产／具体反馈查看 | 现有 assets 下的 revisions 详情及来源定位 | 只读版本不漂移 |
| 结构化理由修订 | papers 下的 feedback-context 版本接口、归档详情折叠表单 | 不影响原 Action.done |
| 分析材料预览 | analysis/previews、回顾页“模型辅助”入口 | GET 不创建外部请求；提交采用显式 POST |
| 用途授权／撤回／来源排除 | 当前工作区阅读分析设置、材料选择器 | 与既有模型连接配置分别表达 |
| 分析提交与进度 | analysis/runs，工作区 `ui.insight_analysis` | 参数只含清单／授权 ID、版本、预算及用途，无私人正文 |
| 候选与确认 | candidates 列表、依据抽屉、确认／修订／关联入口 | 写入用户决定，不能以 GET 触发确认 |
| 方法／证据资产 | 现有资产入口扩展类型化详情 | 旧资产入口继续可用 |

| 阅读画像 | 全部历史内的“研究记忆” | 显式显示不参与推荐，不更名为已确认研究档案 |

沿用现有表单来源检查、错误信封、导航和 htmx 交互；私人草稿不放入 URL／查询参数。相同工作区仍只允许一个 `ui.*` 长任务，冲突引导到现有进度，不另起静默后台排队器。

新任务类型必须覆盖 `UIFlowManager` 的提交、恢复类型列表、取消、原参数重试、进度文案和终态跳转。事实 `ui.review` 不检查模型就绪；模型任务另外校验配置及用途授权，不让新功能破坏离线回顾。

## 13. 运行、故障及成本边界

- **只读阶段**：真实 SQLite 一致快照中选择已知材料与版本，生成清单后释放连接。
- **计算阶段**：事务外调用模型，发送边界再次校验授权和端点；重试／repair 计入同一任务预算。
- **短写阶段**：`BEGIN IMMEDIATE` 校验源版本、授权版本、任务未取消及幂等后保存结果；源已变化时标明过期，不假装基于最新材料。
- **可恢复性**：单篇结果逐批完整保存；重启标记中断，仅用户重试未完成部分。不能因“修复失败”自动扩大模型、费用或材料范围。
- **部分失败**：保留事实版和可用结果，明确缺失篇数；不把少量成功结果标成完整专题。
- **隐私故障**：授权或来源检查失败即停止新发送，不能降级成“默认允许”；清理失败保留可重试状态并明确列出剩余副本。
- **成本**：预览实际材料量和预计调用批次，记录真实 token／调用／repair／重试数据；不知道端点价格时显示价格未知，不猜费用。现阶段不承诺固定货币成本或固定模型质量。

### 14.2 放行条件

1. 第一阶段 6 组返工通过复验；更新验收报告的状态和证据。
2. 没有授权的私人材料，在所有捕获请求中出现次数为零；包括修复、重试和派生摘要。
3. 所有可保存候选均有服务端验证存在的材料引用；直接引文可对照，推测与用户表达可区分。
4. 用户确认、修订、停用和删除在后续回顾、个人导出及派生对象清单中一致；不被下一次模型分析覆盖。
5. 事实回顾、旧报告、旧资产、导入、评分、挖掘和长期队列回归全部通过，画像未进入推荐。
6. 用户可以在不填写新理由、不授权新分析的情况下继续原流程。

先在 1,000／10,000 篇事实底座上验证范围选择不截断，再分别观察多资产／多报告／多候选场景，补上第一阶段主要覆盖论文和评分规模、较少覆盖资产规模的不足。记录材料预算、批次取消和峰值内存，不以静默截断维持速度。
